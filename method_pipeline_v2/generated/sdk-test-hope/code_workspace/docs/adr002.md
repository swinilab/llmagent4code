# ADR 002 – In‑memory AsyncIO Queue for Order Tasks

**Decision:** Use an `asyncio.Queue` with bounded size for background order processing tasks.

**Context:** Satisfies NFR 1.3 (queue management) and NFR 2.1 (graceful degradation) by providing back‑pressure and preventing overload.

**Alternatives considered:**
- External broker (RabbitMQ, Kafka) – adds operational complexity and external dependencies.
- Unbounded Python list – would allow unlimited growth and risk OOM.
Both were rejected to keep the system lightweight and self‑contained.

**Consequences:** Queue is in‑process; if the process crashes, pending tasks are lost unless persisted (addressed by WAL). Simpler deployment but limited scalability beyond a single instance.
