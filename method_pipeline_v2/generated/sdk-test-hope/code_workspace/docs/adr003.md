# ADR 003 – Write‑Ahead Log (WAL) for State Preservation

**Decision:** Implement a simple SQLite‑backed write‑ahead log to persist critical events (order placement, payment, invoice creation).

**Context:** Addresses NFR 2.3 State Preservation, ensuring that after a crash the system can replay pending operations.

**Alternatives considered:**
- Event sourcing framework – adds considerable complexity and external storage.
- Rely on database transaction durability alone – would not capture in‑memory queue state.
Both were rejected for simplicity and minimal external dependencies.

**Consequences:** Adds a lightweight persistence layer; requires careful replay logic to avoid duplicate processing. Suitable for a single‑node deployment.
