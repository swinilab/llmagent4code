# ADR 001 – Use FastAPI with AsyncSQLAlchemy

**Decision:** Adopt FastAPI for the web framework and async SQLAlchemy with SQLite for persistence.

**Context:** Addresses NFR 1.1 (low latency) and NFR 1.2 (high concurrency) by providing an asynchronous, high‑performance stack.

**Alternatives considered:**
- Django REST Framework – heavier, synchronous, higher latency.
- Flask + SQLAlchemy – lacks built‑in async support, would need extra extensions.
Both were rejected due to poorer performance under load.

**Consequences:** FastAPI requires explicit async coding and pydantic models, increasing initial development effort, but yields lower request latency and better resource utilization.
