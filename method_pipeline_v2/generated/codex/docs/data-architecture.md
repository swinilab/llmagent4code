# Context

PostgreSQL is the authoritative data store for every OMS aggregate. Redis holds only expiring, checksummed projections and the event stream; losing Redis cannot lose an accepted HTTP mutation. UUIDv4 identifiers are generated by the service. Monetary values are persisted as fixed-scale `NUMERIC`, calculated with Python `Decimal`, and serialized as two-decimal strings.

# Architecture

## Relational model

| Table | Purpose | Primary relationships and invariants |
|---|---|---|
| `customers` | Actor/customer identity, contact, banking details, and fixed role | UUID PK; soft-delete marker; lengths and role allow-list checked. `orderHistory` is derived from `orders`, newest first, capped at 10,000. |
| `products` | Product description and current base price | UUID PK; price `NUMERIC(8,2)` in `0.01..999999.99`; currency is USD, VND, or EUR. |
| `orders` | Workflow aggregate root and calculated total | FK to active customer; optional unique FK to invoice; total `NUMERIC(10,2)`; version and UTC timestamps; status and timestamp checks. |
| `order_items` | Product quantity and immutable price snapshot | FKs to order/product; unique `(order_id, product_id)` rejects duplicates; quantity `1..1000`; snapshot `NUMERIC(8,2)`. Service limits each order to 100 rows. |
| `invoices` | Immutable billing and amount snapshot | One-to-one FK to an ACCEPTED order; due date cannot precede issue date; status allow-list. Creation advances the order to INVOICED. |
| `payments` | Customer payment submission and accountant decision | FK to an INVOICED order; exact invoice amount; method/status allow-lists. Row locks serialize concurrent review. |
| `outbox_events` | Durable asynchronous domain events | Event UUID is the consumer idempotency key. Unpublished rows are claimed in bounded batches with `FOR UPDATE SKIP LOCKED`. |

The executable ORM schema is in `app/db/models.py`, the initial migration is `alembic/versions/20260820_0001_initial.py`, and equivalent PostgreSQL DDL is in `schema.sql`.

## Relationships

```text
Customer 1 ─── * Order 1 ─── 1..100 OrderItem * ─── 1 Product
                    │
                    ├── 0..1 Invoice
                    └── 0..* Payment

Every aggregate mutation ─── 1 OutboxEvent in the same transaction
```

Orders require a single currency because the public model has one total and no exchange-rate model. Product amounts are copied into order items, order/customer values are copied into invoices, and client-supplied comparison hints are rejected when they differ from the server-derived value.

## State machines

```text
Order:   PLACED → ACCEPTED → INVOICED → PAID → VERIFIED → SHIPPED → CLOSED
           └──────────────→ CANCELLED

Payment: PENDING → VERIFIED
              └→ REJECTED (Order returns PAID → INVOICED)

Invoice: ISSUED/OVERDUE → PAID
                      └→ CANCELLED (reserved lifecycle value)
```

Services lock workflow rows before testing the current state. Invalid syntax/value returns 400, an absent well-formed reference returns 404, and a valid reference in the wrong state returns 409.

## Multiple copies and resynchronization

Redis keys use `oms:entity:<type>:<uuid>`. Each envelope contains the normalized payload, entity version, SHA-256 checksum, and cache timestamp. Reads verify the checksum. A periodic reconciler scans canonical rows in bounded pages, compares version/checksum, repairs drift, and deletes true orphan projections only after a complete canonical scan.
