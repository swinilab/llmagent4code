# Software Requirements Specification (SRS)
## SaaS URL Shortener

---

## 1. Purpose & Scope

This SRS is the single source of truth for building a working SaaS URL Shortener web application. An agent reading this document must be able to produce a runnable codebase with no follow-up questions.

The application must run natively on **Windows, macOS, and Linux** with only `npm install && node server.js` — no compilation toolchains, no Visual Studio Build Tools, no `node-gyp`.

**In scope:** web UI, REST API, authentication, link management, basic analytics, QR codes, two subscription tiers.  
**Out of scope:** native mobile apps, real payment processing, team/org accounts, custom domains, bulk imports.

---

## 2. Tech Stack (Mandatory)

The agent must use exactly this stack. No substitutions.

| Layer | Package | Reason |
|-------|---------|--------|
| **Runtime** | Node.js 20 LTS | — |
| **Framework** | `express` | — |
| **Database** | `prisma` (SQLite provider) | Prebuilt query-engine binaries for all platforms; zero native compilation |
| **Auth** | `jsonwebtoken` + `cookie-parser` | Pure JS; JWT in `httpOnly` cookie |
| **Password hashing** | `bcryptjs` | Pure JS implementation of bcrypt; no native addon, works on Windows without build tools |
| **Short code generation** | `nanoid` | Pure JS; custom alphabet `[a-zA-Z0-9]`, length 6 |
| **QR codes** | `qrcode` | Pure JS; server-side PNG generation |
| **Rate limiting** | `express-rate-limit` | Pure JS |
| **Security headers** | `helmet` | Pure JS |
| **LRU cache** | `lru-cache` | Pure JS; in-process redirect cache |
| **Frontend** | `ejs` templates + vanilla JS | Server-rendered; no build step |
| **Styling** | Plain CSS | No framework, no preprocessor |
| **Email** | `nodemailer` | Logs to stdout when `SMTP_HOST` is unset |
| **Validation** | `zod` | Pure JS schema validation |
| **UUID generation** | `crypto.randomUUID()` | Built into Node.js 20; no extra package |

> **Windows compatibility rule:** Every package in `dependencies` and `devDependencies` must be pure JavaScript (no native addons). If any package would require `node-gyp`, `node-pre-gyp`, Visual Studio Build Tools, or a C/C++ compiler to install, it must be replaced with a pure-JS equivalent.

### Running the App (Windows, macOS, Linux)

```bash
npm install
npx prisma migrate deploy
node server.js
```

App is available at `http://localhost:3000`.

> `npx prisma migrate deploy` downloads a prebuilt Prisma query engine binary for the current OS/arch automatically. No compiler required.

### First-run auto-migration

`server.js` must call `prisma.$executeRawUnsafe` or Prisma's programmatic migrate API to apply pending migrations before `app.listen(...)`. This way `npm install && node server.js` is sufficient without a separate migrate step.

### Running with Docker

```bash
docker compose up
```

The `docker-compose.yml` must mount a named volume at `/app/data` so the SQLite file persists across container restarts.

## 4. Functional Requirements

---

### 4.1 Authentication & Account Management

**FR-AUTH-01** — Registration: `POST /auth/register` accepts `email` + `password`. Validates email uniqueness and password ≥ 8 chars with at least one letter and one digit. Creates the user with `tier = 'free'`. Redirects to `/dashboard` on success.

**FR-AUTH-02** — Login: `POST /auth/login` validates credentials, issues a JWT in an `httpOnly` cookie (expires in 7 days). Redirects to `/dashboard` on success; re-renders login with an error on failure.

**FR-AUTH-03** — Logout: `POST /auth/logout` clears the JWT cookie and redirects to `/`.

**FR-AUTH-04** — Login brute-force protection: after 5 failed login attempts from the same IP within 10 minutes, return `HTTP 429` for 15 minutes.

**FR-AUTH-05** — Password reset: `POST /auth/forgot-password` sends a reset email with a one-time token (valid 1 hour). `POST /auth/reset-password` accepts the token + new password, updates the hash, invalidates the token.

**FR-AUTH-06** — Account settings (`GET /account`): logged-in user can change their password (requires current password) and delete their account (soft-deletes all their links).

> Email verification is omitted. Accounts are fully active immediately on registration.

---

### 4.2 URL Shortening

**FR-SHORT-01** — Any visitor may submit a URL on the home page (`POST /`). The system validates it (must have `http`/`https` scheme and a valid hostname via `zod`), generates a 6-char base-62 short code via `nanoid`, persists the link (`userId = null` for guests), and renders the result on the same page.

**FR-SHORT-02** — Links created by authenticated users are associated with their account and appear in the dashboard.

**FR-SHORT-03** — Pro Users may provide a `customSlug` (3–50 chars, `[a-zA-Z0-9-]`, no leading/trailing hyphens). Slug conflicts return `HTTP 409`.

**FR-SHORT-04** — Pro Users may set an optional `expiresAt` datetime. After expiry the link stops redirecting.

**FR-SHORT-05** — Pro Users may set an optional `password` on a link (stored as a `bcryptjs` hash).

**FR-SHORT-06** — Free Users are capped at 50 active links. Exceeding the cap returns an error with an upgrade prompt.

---

### 4.3 Redirect Service

**FR-REDIR-01** — `GET /:shortCode` resolves the code. Check `lru-cache` (max 1 000 entries) first, then the database. Respond with `HTTP 302 Location: <destinationUrl>`.

**FR-REDIR-02** — Unknown code → `HTTP 404`, render `views/404.ejs`.

**FR-REDIR-03** — Expired link → `HTTP 410`, render `views/expired.ejs`.

**FR-REDIR-04** — Password-protected link → `HTTP 200`, render `views/password-gate.ejs`. `POST /:shortCode/unlock` validates the password with `bcryptjs.compare`; on success set a short-lived signed cookie for that code and redirect. On failure re-render with an error.

**FR-REDIR-05** — Every successful redirect records a click event via `setImmediate` (non-blocking) with: `linkId`, `clickedAt` (UTC ISO string), `ipAddress`, `userAgent`, `referrer`. Click recording must never throw or delay the redirect response.

---

### 4.4 Link Management (Dashboard)

**FR-MGMT-01** — `GET /dashboard` renders a paginated list of the user's links (20 per page). Each row shows: short URL, destination URL (truncated to 60 chars), creation date, status (Active / Expired), total click count.

**FR-MGMT-02** — Supports query params `?sort=createdAt|clicks|slug` (default `createdAt` DESC) and `?status=active|expired|all` (default `all`).

**FR-MGMT-03** — `GET /links/:shortCode/edit` renders an edit form. `POST /links/:shortCode/edit` updates `destinationUrl`. Pro Users also see `expiresAt` and `password` fields.

**FR-MGMT-04** — `POST /links/:shortCode/delete` soft-deletes the link (`deletedAt = now()`). The redirect endpoint returns 404 for soft-deleted codes.

**FR-MGMT-05** — A search input appends `?q=<term>` and filters links by `shortCode` or `destinationUrl` containing the term (Prisma `contains` / SQL `LIKE`).

---

### 4.5 Analytics

**FR-ANAL-01** — `GET /links/:shortCode/stats` renders:
- Total clicks (all time) and unique clicks (distinct IP per 24-hour window)
- Daily click counts for the past 30 days as an HTML `<table>` (CSS bar widths are a bonus)
- Top 5 referrer domains
- Click breakdown by device type: Mobile / Desktop / Bot / Unknown (classified from `User-Agent` string)

**FR-ANAL-02** — Dashboard header shows: total active links, total clicks this calendar month.

**FR-ANAL-03** — Pro Users see a "Download CSV" link (`GET /links/:shortCode/stats/export`) returning a CSV with columns: `timestamp`, `ipAddress`, `deviceType`, `referrer`.

---

### 4.6 QR Codes

**FR-QR-01** — `GET /links/:shortCode/qr` returns a PNG (`Content-Type: image/png`) of a QR code encoding the full short URL.

**FR-QR-02** — The stats and edit pages render an `<img src="/links/:shortCode/qr">` and a download anchor `<a href="/links/:shortCode/qr" download="qr-{shortCode}.png">`.

---

### 4.7 REST API

**FR-API-01** — All endpoints under `/api/v1/`. JSON only. Error envelope:
```json
{ "error": { "code": "ERROR_CODE", "message": "Human-readable message." } }
```

**FR-API-02** — API key management on the account settings page: generate (Free: 1 max, Pro: 5 max), view raw key once on creation, revoke. Keys stored as `crypto.createHash('sha256')` digests; raw key returned only at creation.

**FR-API-03** — API auth: `Authorization: Bearer <api_key>`. Invalid/missing → `HTTP 401`.

**FR-API-04** — Per-key rate limits: Free → 60 req/min, Pro → 600 req/min. Exceeded → `HTTP 429` + `Retry-After` header.

**FR-API-05** — Endpoints:

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/v1/links` | Create short link |
| `GET` | `/api/v1/links` | List links (paginated) |
| `GET` | `/api/v1/links/:shortCode` | Get single link |
| `PATCH` | `/api/v1/links/:shortCode` | Update destination, expiresAt, password |
| `DELETE` | `/api/v1/links/:shortCode` | Soft-delete |
| `GET` | `/api/v1/links/:shortCode/stats` | Click stats |
| `GET` | `/api/v1/account` | Current user + quota |

**FR-API-06** — OpenAPI 3.0 spec served at `GET /api/v1/openapi.json`.

## 5. Non-Functional Requirements (Quality Attributes)

All test commands below run on Windows (PowerShell or CMD), macOS, and Linux. Platform-specific variants are noted where they differ.

---

### 5.1 Performance

**NFR-PERF-01 — Redirect latency**
- **Requirement:** `GET /:shortCode` (cache-warm) responds at p95 ≤ 100 ms.
- **Tool:** k6 (cross-platform binary available at https://k6.io/docs/get-started/installation/)
- **Test script** (`redirect_perf.js`):
  ```js
  import http from 'k6/http';
  import { check } from 'k6';
  export let options = { vus: 20, duration: '30s' };
  export default function () {
    const res = http.get('http://localhost:3000/<shortCode>', { redirects: 0 });
    check(res, { 'is 302': (r) => r.status === 302 });
  }
  ```
  Run: `k6 run redirect_perf.js` — inspect `http_req_duration p(95)`.
- **Threshold:** p95 ≤ 100 ms

**NFR-PERF-02 — API create-link latency**
- **Requirement:** `POST /api/v1/links` responds at p95 ≤ 400 ms under 30 concurrent users.
- **Tool:** k6 (30 VUs, 30 s), valid Bearer token.
- **Threshold:** p95 ≤ 400 ms

**NFR-PERF-03 — Dashboard page load**
- **Requirement:** Lighthouse Performance score ≥ 70, TTI ≤ 5 s (desktop, no throttling).
- **Tool:** `npx lighthouse http://localhost:3000/dashboard --only-categories=performance --output=json` (works on Windows via npx)
- **Threshold:** score ≥ 0.70; TTI ≤ 5 000 ms

---

### 5.2 Availability & Reliability

**NFR-AVAIL-01 — Health endpoint**
- **Requirement:** `GET /health` returns `HTTP 200` `{"status":"ok","db":"ok"}` when healthy; `HTTP 503` when the DB file is inaccessible.
- **Tool (Windows PowerShell):** `(Invoke-WebRequest http://localhost:3000/health).StatusCode`
- **Tool (macOS/Linux):** `curl -s http://localhost:3000/health`
- **Threshold:** 200 + correct body when healthy; 503 when DB is unreachable (tested by temporarily renaming the `.db` file).

**NFR-AVAIL-02 — Crash recovery**
- **Requirement:** After the Node process is killed and restarted, all previously created short links still resolve.
- **How to kill on Windows:** `taskkill /F /PID <pid>` (or close the terminal)
- **How to kill on macOS/Linux:** `kill -9 <pid>`
- **Verification (all platforms):** Restart with `node server.js`, then open each short URL in a browser or run `curl -I http://localhost:3000/<code>`.
- **Threshold:** All 5 test links resolve with HTTP 302 after restart.

---

### 5.3 Security

**NFR-SEC-01 — Security headers**
- **Requirement:** Every response includes `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, and a non-empty `Content-Security-Policy`. Satisfied by using `helmet` middleware.
- **Tool (Windows PowerShell):** `(Invoke-WebRequest http://localhost:3000).Headers`
- **Tool (macOS/Linux):** `curl -sI http://localhost:3000`
- **Threshold:** All 3 headers present.

**NFR-SEC-02 — Password hashing**
- **Requirement:** Passwords stored as `bcryptjs` hashes (`$2b$` prefix). No password field in any API response.
- **Tool:** Query the SQLite file with any SQLite browser (e.g., DB Browser for SQLite, cross-platform) or `npx prisma studio`.
- **Verification:** `SELECT passwordHash FROM User LIMIT 1;` — value starts with `$2b$`.
- **Threshold:** Hash prefix is `$2b$`; `GET /api/v1/account` contains no `password` field.

**NFR-SEC-03 — API rate limit enforcement**
- **Requirement:** A Free-tier key is blocked after 60 requests in 60 seconds.
- **Tool (Windows PowerShell):**
  ```powershell
  1..65 | ForEach-Object {
    (Invoke-WebRequest -Uri http://localhost:3000/api/v1/account `
      -Headers @{ Authorization = "Bearer <key>" } `
      -UseBasicParsing).StatusCode
  }
  ```
- **Tool (macOS/Linux):** `for i in $(seq 1 65); do curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer <key>" http://localhost:3000/api/v1/account; done`
- **Threshold:** At least one `429` response appears in output.

**NFR-SEC-04 — Protected routes require auth**
- **Requirement:** `/dashboard`, `/links/*`, `/account`, `/api/v1/*` return HTTP 401 or redirect to `/login` without a valid session.
- **Tool (Windows PowerShell):** `(Invoke-WebRequest -Uri http://localhost:3000/dashboard -MaximumRedirection 0 -ErrorAction SilentlyContinue).StatusCode`
- **Tool (macOS/Linux):** `curl -sI http://localhost:3000/dashboard`
- **Threshold:** 302 redirect to `/login` (UI routes) or 401 (API routes).

### 5.4 Usability

**NFR-USE-01 — Core task in 3 interactions**
- **Requirement:** A logged-in user can shorten a URL and copy the result in ≤ 3 interactions from the dashboard.
- **Tool:** Manual test in any browser.
- **Threshold:** ≤ 3 interactions.

**NFR-USE-02 — Mobile layout**

  document.documentElement.scrollWidth > document.documentElement.clientWidth

**NFR-USE-03 — Inline form errors**

- **Threshold:** Error message visible in DOM within 300 ms; no full-page reload.

### 5.5 Data Integrity

**NFR-DATA-01 — Short code uniqueness**
- **Requirement:** No two links share the same `shortCode`.
- **Tool:** After creating 500 links via the API, open `npx prisma studio` and run:
  ```sql
  SELECT shortCode, COUNT(*) c FROM Link GROUP BY shortCode HAVING c > 1
  ```
- **Threshold:** Query returns 0 rows.

**NFR-DATA-02 — Click count accuracy**
- **Requirement:** `total_clicks` from the stats API matches the raw row count in `ClickEvent` for the same link.
- **Tool:** Hit a short URL 50 times, wait 2 s, compare API response `totalClicks` vs Prisma Studio count.
- **Threshold:** Values are equal.

## 6. Prisma Data Model

File: `prisma/schema.prisma`

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "sqlite"
  url      = env("DATABASE_URL")
}

model User {
  id            String    @id @default(uuid())
  email         String    @unique
  passwordHash  String
  tier          String    @default("free")   // "free" | "pro"
  createdAt     DateTime  @default(now())
  deletedAt     DateTime?

  links         Link[]
  apiKeys       ApiKey[]
  resetTokens   PasswordResetToken[]
}

model Link {
  id             String    @id @default(uuid())
  userId         String?
  user           User?     @relation(fields: [userId], references: [id])
  shortCode      String    @unique
  destinationUrl String
  passwordHash   String?
  expiresAt      DateTime?
  createdAt      DateTime  @default(now())
  updatedAt      DateTime  @updatedAt
  deletedAt      DateTime?

  clicks         ClickEvent[]

  @@index([shortCode])
  @@index([userId])
}

model ClickEvent {
  id         String   @id @default(uuid())
  linkId     String
  link       Link     @relation(fields: [linkId], references: [id])
  clickedAt  DateTime @default(now())
  ipAddress  String?
  userAgent  String?
  referrer   String?
  deviceType String   @default("unknown")  // "mobile"|"desktop"|"bot"|"unknown"

  @@index([linkId])
}

model ApiKey {
  id          String    @id @default(uuid())
  userId      String
  user        User      @relation(fields: [userId], references: [id])
  keyHash     String
  label       String
  createdAt   DateTime  @default(now())
  lastUsedAt  DateTime?
  revokedAt   DateTime?

  @@index([userId])
}

model PasswordResetToken {
  id        String    @id @default(uuid())
  userId    String
  user      User      @relation(fields: [userId], references: [id])
  tokenHash String
  expiresAt DateTime
  usedAt    DateTime?
}
```

After editing `schema.prisma`, the agent must run `npx prisma migrate dev --name init` to generate the initial migration. The app calls `prisma.$executeRaw` or uses Prisma's `migrate deploy` programmatically on startup so the schema is always up to date.

## 7. API Request / Response Contracts

### `POST /api/v1/links`

**Request:**
```json
{
  "destinationUrl": "https://example.com/some/long/path",
  "customSlug": "my-promo",
  "expiresAt": "2026-12-31T23:59:59Z",
  "password": "hunter2"
}
```
`customSlug`, `expiresAt`, `password` are optional and Pro-only. Sending them as a Free user → `HTTP 403`.

**Response `201`:**
```json
{
  "shortCode": "aB3xZ9",
  "shortUrl": "http://localhost:3000/aB3xZ9",
  "destinationUrl": "https://example.com/some/long/path",
  "expiresAt": null,
  "createdAt": "2026-06-08T10:00:00.000Z"
}
```

**Errors:** `400` bad URL, `403` Pro-only feature, `409` slug taken, `422` quota exceeded.

---

### `GET /api/v1/links`

**Query params:** `page` (default 1), `perPage` (default 20, max 100), `status` (`active|expired|all`), `sort` (`createdAt|clicks|slug`).

**Response `200`:**
```json
{
  "data": [
    {
      "shortCode": "aB3xZ9",
      "shortUrl": "http://localhost:3000/aB3xZ9",
      "destinationUrl": "https://example.com/...",
      "status": "active",
      "totalClicks": 42,
      "createdAt": "2026-06-08T10:00:00.000Z",
      "expiresAt": null
    }
  ],
  "meta": { "page": 1, "perPage": 20, "total": 7 }
}
```

---

### `GET /api/v1/links/:shortCode/stats`

**Response `200`:**
```json
{
  "shortCode": "aB3xZ9",
  "totalClicks": 104,
  "uniqueClicks": 87,
  "clicksByDay": [
    { "date": "2026-06-01", "count": 12 }
  ],
  "topReferrers": [
    { "domain": "twitter.com", "count": 34 }
  ],
  "byDevice": {
    "mobile": 60,
    "desktop": 40,
    "bot": 4,
    "unknown": 0
  }
}
```

---

### `GET /api/v1/account`

**Response `200`:**
```json
{
  "id": "uuid",
  "email": "user@example.com",
  "tier": "free",
  "quota": { "used": 23, "limit": 50 }
}
```
`limit` is `null` for Pro users.
