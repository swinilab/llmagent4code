# ADR 004 – Write‑Ahead Log (WAL) for crash recovery

**Decision**: Persist critical state changes (order creation, payment, invoice) to a plain‑text WAL file before committing to the SQLite database.

**Context**: Meets NFR 2.3 (State Preservation) by allowing the application to replay pending operations after an unexpected crash.

**Alternatives considered**:
- SQLite transaction log – opaque and harder to replay at application level.
- External event store (Kafka) – unnecessary overhead for this scope.

**Consequences**: Simple implementation; WAL grows over time but is truncated after successful replay on startup. Relies on the file system being reliable.
