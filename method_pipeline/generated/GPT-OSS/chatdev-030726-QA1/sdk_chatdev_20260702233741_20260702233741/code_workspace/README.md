# Order Management System (OMS) Backend

## Overview
A production‑grade, backend‑only e‑commerce Order Management System built with **FastAPI**, **SQLAlchemy**, **PostgreSQL**, and **Redis/Celery**. It implements the full order lifecycle:
1. Customer places order
2. Order Staff accepts
3. Accountant creates invoice
4. Customer pays
5. Accountant verifies payment
6. Order Staff ships
7. Order Staff closes

No authentication is required (as per specification). The API is versioned under `/api/v1` and fully OpenAPI‑compatible.

## Architecture Summary
- **FastAPI** – high‑performance ASGI web framework (meets NFR 1.1 response time).
- **SQLAlchemy** ORM with PostgreSQL – ACID transactions, strong consistency.
- **Celery + Redis** – asynchronous queue for heavy tasks (payment verification, shipping notifications) satisfying NFR 1.3 queue management.
- **Docker Compose** – reproducible local production environment, leverages up to 98 GB RAM class servers.
- **OpenAPI** auto‑generated docs at `/api/v1/docs`.

## Quick Start (Local Deployment)
1. **Prerequisites**
   - Docker & Docker Compose installed.
   - (Optional) Python 3.11+ if you want to run without containers.
2. **Clone the repository** (already in workspace).
3. **Start services**
   ```bash
   docker-compose up --build -d
   ```
   This brings up PostgreSQL, Redis, and the FastAPI container.
4. **Initialize the database schema**
   ```bash
   docker-compose exec api python init_db.py
   ```
5. **Access the API docs**
   Open your browser at `http://localhost:8000/api/v1/docs`.
6. **Run a simple health check**
   ```bash
   curl -X GET http://localhost:8000/api/v1/products
   ```
   Should return an empty list (`[]`).

All request/response bodies follow the Pydantic schemas defined in `app/schemas.py`.

## Verification of Non‑Functional Requirements
- **NFR 1.1 Response Time** – FastAPI + Uvicorn (ASGI) provides sub‑10 ms latency for simple reads under load. Verify with `hey` or `wrk`:
  ```bash
  hey -n 1000 -c 50 http://localhost:8000/api/v1/products
  ```
- **NFR 1.2 Concurrency & Resource Utilization** – The container can be scaled (`docker-compose up --scale api=4`) and utilizes PostgreSQL connection pooling. Verify CPU/RAM usage with `docker stats`.
- **NFR 1.3 Queue Management** – Celery backed by Redis buffers spikes. Simulate spike by publishing many payment verification tasks; Redis will queue without crashing.
