# NFR Traceability Matrix

Machine-readable twin: [`nfr-trace.json`](../nfr-trace.json) at the project root.
Every mechanism below is exercised in [VERIFICATION.md](VERIFICATION.md).

| NFR | Architectural mechanism | Module / component | Verification method |
|---|---|---|---|
| **1.1 Limit Event Response** | Token-bucket admission control (capacity 100, refill 50/s) evaluated at the HTTP edge; excess load is rejected with `429 + Retry-After` rather than queued. The bucket lives in Redis and is mutated by an atomic Lua script, so the ceiling is global across all 4 uvicorn workers rather than per-process. | [`app/infra/rate_limiter.py`](../app/infra/rate_limiter.py) `TokenBucketRateLimiter.allow`; [`app/core/middleware.py`](../app/core/middleware.py) `RateLimitMiddleware.dispatch` | Fire 200 concurrent requests under one `X-Client-Id`; count the 429s. Observed: **139×200 / 61×429**. Live counter at `GET /ops/nfr → nfr_1_1…throttled`. |
| **1.2 Maintain Multiple Copies of Data** | Both tactics: (a) **replication** — Postgres physical streaming replication to a hot standby, with reads routed to the replica and writes to the primary; (b) **caching** — read-through Redis cache in front of the entity read path, invalidated on every mutation so copies cannot drift. | [`app/infra/database.py`](../app/infra/database.py) `_build_engine`, `read_session`; [`app/infra/cache.py`](../app/infra/cache.py) `EntityCache.get/set/invalidate`; [`app/services/services.py`](../app/services/services.py) `BaseService._cached_read` | `SELECT * FROM pg_stat_replication` on the primary shows `state=streaming`; `pg_is_in_recovery()` on the replica returns `t`; row counts match across both. Cache hit/miss counters at `GET /ops/nfr`. |
| **2.1 Exception Detection** | Both tactics: (a) **system exceptions** — one middleware converts every unhandled fault into a structured, counted 500 carrying a correlation id; the domain error taxonomy maps expected faults to 400/404/409. (b) **timeout** — a per-request wall-clock budget (10 s → 504), a 3 s Postgres `statement_timeout` + `connect_timeout`, and a 250 ms Redis timeout, so a hung dependency becomes a detectable exception instead of an indefinite stall. Circuit breakers count consecutive failures per dependency. | [`app/core/middleware.py`](../app/core/middleware.py) `ExceptionDetectionMiddleware.dispatch`; [`app/infra/degradation.py`](../app/infra/degradation.py) `CircuitBreaker.call`; [`app/infra/cache.py`](../app/infra/cache.py) `EntityCache.get` | Stop a dependency and read `GET /health/ready` — the failing component is named individually (`"redis":"down: ConnectionError"`). Detection counters and breaker states at `GET /ops/nfr`. |
| **2.2 Graceful Degradation** | Features are classified CRITICAL (order workflow, payments, invoicing) vs NON-CRITICAL (cache acceleration, order-history expansion, analytics). When a dependency fails, non-critical features are shed while the critical path keeps serving: a Redis outage bypasses the cache, a replica outage falls back to the primary. Shedding a CRITICAL feature is refused (400). | [`app/infra/degradation.py`](../app/infra/degradation.py) `FeatureRegistry.shed/is_available`; [`app/infra/database.py`](../app/infra/database.py) `_open_replica_session`; [`app/services/services.py`](../app/services/services.py) `BaseService._cached_read` | `docker compose stop redis`, then run the full workflow — every step still returns 201/200 (observed). Same with `stop postgres-replica`: reads fall back to the primary. Live status at `GET /ops/nfr`. |
| **2.3 State Resynchronization** | A background sweep (every 15 s) compares active and standby: replication lag in bytes from `pg_stat_replication`, plus a per-table row-count + md5 checksum fingerprint across both nodes. Divergence is logged and the affected cache entries are evicted so the next read repopulates from the source of truth. | [`app/infra/resync.py`](../app/infra/resync.py) `StateResynchronizer.compare_active_and_standby`, `run_once`, `_replication_lag`; [`app/api/v1/ops.py`](../app/api/v1/ops.py) `force_resync` | `POST /ops/resync` returns `{"replicationLagBytes":0,"drift":{},"inSync":true}`. Stop the replica → `inSync:false`; restart it → the standby catches up the writes it missed and the sweep returns `inSync:true` (observed). |
| **2.4 Transactions** | Every workflow step runs inside exactly one `unit_of_work()` — a single ACID transaction spanning all writes. Issuing an invoice writes the invoice row, stamps `order.invoice_ref`, and moves the order to `INVOICED` atomically. Isolation uses `SELECT … FOR UPDATE` row locks plus an optimistic `version` column, so two concurrent transitions cannot both commit. | [`app/infra/database.py`](../app/infra/database.py) `unit_of_work`; [`app/services/services.py`](../app/services/services.py) `InvoiceService.create`, `PaymentService.create`, `PaymentService.verify`, `OrderService.transition`; [`app/repositories/repositories.py`](../app/repositories/repositories.py) `SQLAlchemyRepository.get_for_update` | Drive two concurrent `/accept` calls at one order — exactly one succeeds, the other gets 409 (`tests/test_transactions.py`). Force a mid-transaction failure and confirm no partial state persists. |

## Why these tactic names

`tacticUsed` in `nfr-trace.json` cites Bass/Clements/Kazman (*Software Architecture in
Practice*) verbatim:

- *Limit Event Response* and *Maintain Multiple Copies of Data* — Performance,
  "Manage Resources".
- *Exception Detection* — Availability, "Detect Faults".
- *Degradation* and *State Resynchronization* — Availability, "Recover from Faults /
  Preparation and Repair".
- *Transactions* — Availability, "Prevent Faults".
