\begin{abstract}
% todo: abstract 
Domain-driven design (DDD) has widely been used to develop RESTful software in a range of programming language platforms. The use of code generators in these technologies helps significantly increase productivity and achieve large scale software reuse.
%\textbf{Problem/Challenges:}
However, there been no work that address incremental construction of RESTful full stack software (RFS) at both the module and software levels.
%\textbf{Proposal/Contributions:}
In this paper, we propose a generative module-based method for RFS to bridge this gap.
%\textbf{Method}: 
We characterise RFS and realise this in a module-based DDD software architecture, named \mosar. Our method takes as input a software configuration and the required software assets and automatically generates a module-based RFS software. We present algorithms for the frontend and backend generation functions. The backend software consist of web service modules. The frontend software consists of modules that are designed with single-page views. Each view can be nested to reflect the containment tree of the module.
%\textbf{Result}:
We demonstrate by implementing the generators for two popular platforms (React and Spring Boot). The evaluation shows that the generators are able to support large software.

\end{abstract}

\textbf{Example: \courseman.} %\label{sect:example}
% + todo: example
% update
To illustrate the concepts presented in this paper, we adopt the software example, named course management (\courseman), that we used in previous works~\cite{le_jdomainapp_2019,le_generative_2020}. This example is scoped around a domain model whose elements are represented by the following fundamental UML \cite{omg_unified_2015} meta-concepts: class, attribute, operation, association, association class and generalisation.
%
The \courseman's domain model consists of six domain classes and associations between them.
Class \clazz{Student} represents the domain concept Student
Class \clazz{CourseModule} represents the \clazz{CourseModule}s
that are offered to students.
%We specifically label the \clazz{Student}'s end of the many-many association between this class and \clazz{CourseModule} with the role ``students''.
Class \clazz{Address} represents the addresses where \clazz{Student}s live as they undertake their studies. The study arrangement involves enrolling each \clazz{Student} into one or more \clazz{CourseModule}s. Class \clazz{Enrolment} represents the enrollment records.
